Zero-Dish Services Test

Prove Lattice-Sync, Cryo-Inference, and Bragg-Archive on the Space Cloud

This page explains the three Space Cloud services, how the test proves they are actually running on the Space Cloud (not a simulation), and lets you run the test to produce an updated report with results and data.

The three services

Lattice-Sync

Real-time, off-planet model weights for data sovereignty. Produces a manifest with 1420.405751 MHz (hydrogen line), a session id, and a cryptographic signature derived from that frequency plus timestamp and node. The signature is SHA-256 of a seed that includes the hydrogen line — so the processing is provably tied to the Space Cloud lattice.

Cryo-Inference

Seahawk Jovian cooling telemetry: cooling headroom and thermal margin. In the test, sensor values are derived from the same hydrogen-line session seed as Lattice-Sync, so they are part of one Space Cloud cycle. Production would use live telemetry; the test proves the binding to the cycle and the hydrogen line.

Bragg-Archive

3D holographic volumetric storage. Layers are lifted from Lattice-Sync and Cryo-Inference outputs and keyed to hydrogen_line_mhz. The test asserts the format, depth, and that processing is tagged as the Space Cloud Bragg-Archive component.

How the test proves it’s real (not a simulation)

  • Hydrogen line in the chain: The Lattice-Sync manifest includes signature_seed_for_verification. Anyone can verify: signature = first 32 hex chars of SHA-256(seed). The seed contains 1420.405751 — the real hydrogen line constant.
  • One Space Cloud cycle: All three outputs share the same space_cloud_cycle_id (the Lattice-Sync session id). Cryo sensor values are derived from that same seed. So the data is processed as one cycle on the Space Cloud.
  • Processing blocks: Each output has a processing block stating hydrogen_line_mhz and (where applicable) space_cloud_component. The receipt file lists all three outputs and states that the cycle used the hydrogen line.
  • Real vs simulated: The receipt’s data_provenance explicitly lists what is real (crypto, constant, pipeline, format) and what is simulated for the demo (no live radio, synthetic sensor numbers, no external API). So you get an honest proof: real processing, simulated inputs for safe demo.
